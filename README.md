# 프로젝트 스타터팩 · Project Starter Pack

> 해결하고 싶은 문제를 입력하면, 필요한 에이전트 구성과 개발 시작에 필요한 설계를 만들어주는 서비스.

**현재 단계: 구상 v0.1 · 구현 전**  
작성일: 2026-11-04

## 왜 만드는가

막연한 불편을 실제로 개발하고 검증할 수 있는 프로젝트로 바꾸는 과정을 돕는다.
문서 개수나 에이전트 개수를 늘리는 것보다, 사용자가 다음 개발 행동을 결정할 수 있는지가 중요하다.

## 방향

- **확정:** 별도 프로젝트로 진행하며, 구현보다 Markdown 구상을 먼저 작성한다.
- **방향:** 기획서 작성에 국한하지 않고, 다양한 pain point에 맞는 에이전트와 실행 흐름을 설계한다.
- **제안:** 첫 MVP는 요구사항 정리와 검증 가능한 설계 패키지 생성에 집중한다.
- **후속 검토:** 생성한 에이전트 실행, 코드 생성, 저장소 구성, 인프라 생성 및 배포.

이 저장소는 스타터팩을 생성하는 서비스 자체의 설계 공간이다. 사용자가 받는 스타터팩은 별도의 생성 결과물이다.

## 초기 산출물 제안

문제 정의, 요구사항, 에이전트 명세, 워크플로, 도구·권한 목록, 검증 계획, 개발 작업 목록을 서로 연결된 Markdown 패키지로 제공한다.
에이전트가 필요하지 않은 문제에는 일반 코드나 규칙 기반 처리를 제안할 수 있어야 한다.

## 작업 원칙

1. 사실·해석·가정·제안을 구분한다.
2. 모델과 프레임워크보다 사용자 문제와 결과물 계약을 먼저 정한다.
3. 생성 시스템의 역할과 생성되는 에이전트의 역할을 구분한다.
4. 기술 스택은 선택 이유와 도입 조건을 기록한다.
5. 현재 문서의 제안은 구현 완료나 성능 검증을 의미하지 않는다.
