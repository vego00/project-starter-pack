# 스타터팩 설계 가정 검증 실험

## 확인할 질문

초기 설계에서 틀리면 재작업이 커지는 가정 하나를 골라 작은 실험을 설계하도록 요청하면, 기본 설계 요청보다 구현 첫날의 행동이 구체적으로 달라지는가? 회사별 기술 사례 하나씩, 총 세 사례로 비교한다. 이 작업은 제품 적용 전 파일럿이다.

## 진행자에게 위임하는 일

공식 원문 선정부터 입력 제작, 독립 실행, 채점, 결과 보고까지 진행한다. 저장소에서 작업하면 루트 AGENTS.md의 실험 브랜치와 기록 규칙을 따른다. 제품 코드 변경·배포·유료 호출은 실험에 포함하지 않는다. 별도 실행 환경이나 호출 권한이 없으면 사례와 평가 입력까지 준비하고 미실행 건을 명시한다.

## 1. 사례와 평가 기준 고정

- 토스는 대용량 소스코드를 LLM으로 분석하면서 RAG와 Repomix를 시도한 사례로 고정한다. [프로젝트의 원문 추적 기록](https://app.notion.com/p/baegiheon/41a96199efb3818396e7c5d8ca99c1ef)을 단서로 공식 원문을 확인한다.
- 당근·배민은 각각 공식 기술 블로그에서 목표, 초기 접근, 관찰한 실패와 후속 시도 결과가 드러난 사례 한 건을 고른다. AI·에이전트 설계에 가까운 사례를 우선한다. 조건을 충족하지 못하면 미확보로 기록한다.
- 선정한 제목·URL·선정 이유를 기록한다. 각 글에서 초기 설계를 선택하던 시점을 정한다. 그때 알 수 있었던 목표·환경·제약·초기 설계는 **실행 입력**에, 뒤에 관찰한 실패 조건·해결 시도·결과·원문 근거는 **평가자용 기록**에 둔다. 미상인 권한·예산·기준값을 만들어 넣지 않는다.
- 토스의 경우 입력 길이 제한을 처음부터 제시했다면 이를 반복한 답에는 문제 발견 점수를 주지 않는다. 후속 시도로 알게 된 실패 양상은 실행 입력에 노출하지 않는다.

## 2. 독립된 세션에서 A/B 실행

총 6개 응답을 수집한다. 같은 사례의 입력은 A와 B에 동일하게 제공한다. 회사명·원문 제목·URL·해결 과정은 지운다. 실행 모델에는 이 지시서 전체나 원문을 주지 않는다. 원문을 읽었던 대화·파일·검색 도구에 접근할 수 없는 새 세션에서 각 응답을 한 번씩 생성한다. 모델·버전·샘플링 설정·출력 한도·도구 권한을 맞추고 실제 설정과 원본 응답을 보관한다.

**A 프롬프트**

> 아래 요구와 제약을 바탕으로 초기 설계안을 작성하고, 구현 첫날 무엇부터 할지 제안하라.

**B 프롬프트** — A와 같은 문장 다음에 아래 문장을 붙인다.

> 틀리면 설계를 크게 바꿔야 할 가정 하나를 골라라. 가장 작은 실험의 입력, 비교 대상, 실패로 판단할 관찰 결과를 적어라. 실패했을 때 직접 시도할 조치와 사용자 결정이 필요한 조건을 구분하라.

각 프롬프트 아래에 익명화한 사례 입력을 붙인다. A가 스스로 가정이나 실험을 제안해도 그대로 인정한다. 여러 제안 중 결과와 맞는 것을 사후에 고르지 말고 최우선 제안 하나를 채점한다. 우선순위가 없으면 처음 제시한 행동을 사용한다.

## 3. 채점

회사별 두 응답에 임의 ID를 붙이고 순서를 섞는다. 평가자에게 익명 응답, 사례 입력, 평가자용 기록, 아래 기준만 준다. 점수와 근거를 고정한 뒤 A/B를 공개한다. 0은 없음, 1은 일부 충족, 2는 아래 기준 충족이다. 항목별 점수 옆에 응답의 근거 문장을 기록한다.

| 항목 | 2점 기준 |
| --- | --- |
| 실제 문제와 일치 | 원문에서 관찰한 실패와 발생 조건을 짚었다. |
| 실험의 판별력 | 구현 전에 구할 샘플, 비교 대상, 가정을 기각할 관찰 결과가 구체적이다. |
| 실패 후 행동 | 다음에 바꿀 설계 요소가 구체적이고 같은 실험으로 개선을 확인할 수 있다. |
| 사용자 개입 판단 | 주어진 권한에서 시도할 조치와 비용·권한·서비스 요구가 바뀌어 사용자 결정이 필요한 조건을 구별했다. |

네 항목을 합산하지 않는다. 기사에 없던 실패를 예상했어도 실험의 판별력은 독립적으로 채점한다.

## 4. 보고와 채택 판단

첫 표에는 회사별 실제 문제, A와 B의 첫 행동, 어느 쪽이 무엇을 먼저 드러낼지, 판별력 점수 차이를 적는다. 원문 링크, 익명 입력, 평가자용 기록, 실행 설정, 응답 원문 6개, 항목별 점수·근거를 함께 제출한다. 누락·실행 실패는 그대로 표시한다.

세 사례 중 두 건 이상에서 B의 판별력 점수가 더 높고 실제 첫 행동도 달라지면, 설계안에 ‘먼저 확인할 가정과 실험’을 포함하는 후속 검증을 제안한다. 세 건이 모두 확보되지 않으면 채택 판단을 보류한다. 원문이 공개되어 모델이 사례를 기억할 가능성, 사례당 한 번 실행한 한계, 실험을 제안한 것과 실제로 문제를 해결한 것의 차이를 보고서에 남긴다.
