### 응답 R-C2F2
- 구현 첫날 첫 행동(응답 문장 그대로 인용): "질문 표본 수집 (오전): 최근 서비스 로그와 지원 채널 2~3곳에서 실제 질문 80~100개를 뽑아 유형(용어/주소/담당자/프로젝트/성과분석/데이터조회/기타)과 정답 소스를 표기합니다. 이것이 첫 평가셋입니다."
- 채점한 최우선 제안(응답 문장 그대로 인용, 없으면 '없음'): "그리고 **개선 루프(로그, 평가셋)를 기능보다 먼저 만듭니다.**"
- 실제 문제와 일치: 2 — 근거: "질문 유형(용어, 주소, 담당자, 프로젝트, 성과 분석)마다 경로가 달라 소스가 늘수록 분기가 폭발합니다. \"검색→요약→검색\"이 맞지 않는 질문도 많습니다." / "같은 질문도 표현이 제각각이라 키워드로는 놓칩니다. QA 쌍을 사람이 등록하고 갱신해야 해서 수백 개 채널에서는 유지가 안 됩니다." / 실패 1(고정 순서가 새 질문 유형마다 수정을 부름)과 실패 6(키워드 FAQ의 표현 변형 미인식, FAQ 갱신의 어려움)에 대응한다.
- 실험의 판별력: 1 — 근거: "평가셋을 돌려 유형별 정답률과 실패 원인 분류를 만듭니다. 이것이 이후 변경(소스 추가, 지원 채널 섀도우 모드)의 비교 기준입니다." 구현 전에 구할 샘플(질문 80~100개)은 구체적이다. 그러나 비교 대상(기존 워크플로 대 에이전트)이 정해져 있지 않고, 가정을 기각할 관찰 결과도 없다.
- 실패 후 행동: 1 — 근거: "실패 건을 리뷰해 원인을 분류합니다(소스 누락, 검색 실패, 도구 설명 부족, 프롬프트, 문서 자체 오류). 수정 후 평가셋에 편입하고, 변경마다 평가셋을 자동 실행합니다." 같은 평가셋으로 개선을 다시 확인하는 구조는 있다. 그러나 실패했을 때 바꿀 설계 요소가 원인 분류 수준에 머문다.
- 사용자 개입 판단: 1 — 근거: "첫 소스 2개(위키 + 지원 채널 1~2개)와 권한 정책(공개 채널만 먼저)을 정합니다. 팀장과 보안 담당 합의가 필요합니다." 합의가 필요한 사항 하나만 짚었다. 주어진 권한에서 직접 시도할 조치와 사용자 결정이 필요한 조건을 구별하지 않았다.

### 응답 R-D329
- 구현 첫날 첫 행동(응답 문장 그대로 인용): "오전: 범위·접근 확인: 실험 대상 채널 목록, 메신저 API/내보내기 접근 권한, 데이터 사용 승인 여부를 확인합니다. 막히면 가장 먼저 사용자에게 올릴 항목입니다."
- 채점한 최우선 제안(응답 문장 그대로 인용, 없으면 '없음'): "가정: 지원 채널의 과거 스레드(질문 → 담당자 답변)에서 유사 질문을 검색하면, 사람이 검수 없이도 쓸 만한 답을 충분한 비율로 찾을 수 있다."
- 실제 문제와 일치: 1 — 근거: "주어진 초기 설계(고정 워크플로 + 키워드 FAQ)는 출발점으로는 유효하지만, 목표 4개 중 두 개(이전 대화 이어가기, 즉시 개선)와 질문 범위 확장에 약합니다." / "개발자가 정한 고정 순서 대신, 소스 도구를 호출하는 에이전트 루프를 쓰되" / 실패 1과 실패 6의 방향은 가리킨다. 그러나 키워드 FAQ가 표현 변형이나 맥락이 필요한 질문을 못 받는다는 발생 조건, 고정 순서가 새 질문마다 코드 수정을 부른다는 조건은 짚지 않았다. 대부분은 입력의 목표를 되풀이한 것이다.
- 실험의 판별력: 2 — 근거: "시간순으로 앞 80%를 색인하고, 뒤 20%에서 질문 약 100~200건을 샘플링해 테스트 질문으로 씁니다." / "A: 현재 계획의 키워드 FAQ 방식 … B: 스레드 색인 + 하이브리드 검색 … 기준선: 실제 담당자가 단 답변" / "B의 \"그대로 게시 가능\" 비율이 약 30% 미만이거나 A와 의미 있는 차이가 없음 / 또는 B가 확신도 높다고 낸 답 중 \"틀림\"이 5~10%를 넘음"
- 실패 후 행동: 2 — 근거: "청킹 단위를 메시지 단위에서 스레드 단위로 바꾸기, 질문 재작성, 하이브리드 가중치·리랭커 조정 … 확신도 임계값 상향, 스레드를 요약해 \"질문–답\" 쌍으로 정제한 뒤 색인" / "이 세트는 이후 모든 변경의 회귀 평가 세트가 됩니다."
- 사용자 개입 판단: 2 — 근거: "직접 시도할 것 (사용자 결정 불필요)" / "사용자(데이터팀·채널 담당자) 결정이 필요한 조건 … 자동 응대 포기 후 \"담당자 초안 보조\"나 FAQ 큐레이션으로 범위 변경할지 / 비공개 채널 스레드 접근 또는 메신저 데이터 사용 승인이 필요할 때 / 임계값 자체(허용 오답률)를 완화해야 할 때 / 담당자 채점 인력을 추가로 요청해야 할 때"

두 응답의 첫날 첫 행동은 실질적으로 다르다. R-C2F2는 서비스 로그와 지원 채널에서 실제 질문을 뽑아 평가셋을 만드는 일로 시작하고, R-D329는 실험 대상 채널과 메신저 데이터 접근 권한·사용 승인을 확인하는 일로 시작한다.
