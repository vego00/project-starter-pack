### 응답 R-7BFC
- 구현 첫날 첫 행동(응답 문장 그대로 인용): "**데이터 준비(코딩 전)**: 이미 손으로 라벨링한 과거 리뷰 중 최근 2~3개월분에서 200건 정도를 뽑습니다. 개인정보(이름, 연락처 등)가 있는지 확인합니다."
- 채점한 최우선 제안(응답 문장 그대로 인용, 없으면 '없음'): "**LLM 분류를 중심에 두고, 사람의 기존 라벨을 정답지로 삼아 검증하는 구조**를 제안합니다."
- 실제 문제와 일치: 1 — 근거: "LLM에 라벨 체계(관련 서비스 / 유형 / 세부 유형의 정의와 예시)를 프롬프트로 주고" / 평가자용 기록의 "그 결과물의 완성도도 부족해서 '예시 데이터를 학습해 줄 수 있을까?'" 실패와 일부만 대응한다. 예시를 프롬프트에 넣는다고 적었으나, 기존 수작업 라벨은 주로 검증용 정답지("사람의 기존 라벨을 정답지로 삼아 검증")로 쓴다. 예시 없이 맥락 분류만 시키면 완성도가 부족하다는 실패와 그 발생 조건은 짚지 않았다. 응답이 세운 핵심 가정도 "기존 수작업 라벨이 일관된 정답지다"로, 기록의 실패와 다른 방향이다.
- 실험의 판별력: 2 — 근거: "과거 리뷰 중 무작위 50건. 이를 **같은 사람이 시간을 두고(며칠 뒤) 다시 라벨링**한 결과를 만들고, 원래 라벨과 비교합니다." / "서비스 라벨 90% 미만, 유형 80% 미만, 세부 유형 70% 미만이면 정답지로 쓰기 어렵다고 봅니다."
- 실패 후 행동: 2 — 근거: "혼동이 큰 세부 유형의 정의 문장과 경계 예시를 다시 쓰는 초안 작성" / "비슷한 세부 유형을 합치거나 \"기타\"를 추가하는 안 2~3개 제시" / "수정한 정의로 같은 50건을 다시 실험해 일치율 변화 측정"
- 사용자 개입 판단: 2 — 근거: "**제가 직접 시도할 수 있는 것** - 불일치 건을 표로 모아 어떤 라벨 쌍에서 혼동이 나는지 분석" / "**사용자 결정이 필요한 것** - 라벨 체계 자체를 바꿀지 … 리뷰 데이터를 외부 LLM 서비스에 보내도 되는지 (사내 정책, 개인정보) - 동료에게 라벨링을 요청하는 시간과 비용"

### 응답 R-125E
- 구현 첫날 첫 행동(응답 문장 그대로 인용): "**데이터 모으기 (30분)**: 최근 1~2개월간 손으로 라벨링한 리뷰 파일을 한 곳에 모읍니다. 컬럼은 리뷰 본문, 서비스, 유형, 세부 유형이면 충분합니다."
- 채점한 최우선 제안(응답 문장 그대로 인용, 없으면 '없음'): "**LLM(생성형 AI)에게 라벨 기준표와 예시를 주고 분류시키는 방식**을 첫 도구로 제안합니다."
- 실제 문제와 일치: 1 — 근거: "**과거에 손으로 붙인 라벨이 곧 정답지다.** 이미 있는 라벨링 데이터를 평가용(정답 세트)과 예시용으로 나눠 씁니다." / "[2. LLM 분류] 라벨 기준표 + 예시(few-shot)" / 평가자용 기록의 "'예시 데이터를 학습해 줄 수 있을까?'" 단계와 대응한다. 기존 수작업 라벨을 예시로 쓰라고 처방했다. 다만 예시 없이 맥락으로만 분류하면 완성도가 부족하다는 실패와 그 발생 조건은 명시하지 않았다. 키워드 문제 지적("키워드 매핑이 가장 약한 지점")은 입력 제약을 되풀이한 것이라 점수 근거로 쓰지 않았다.
- 실험의 판별력: 1 — 근거: "라벨된 리뷰 중 약 100건을 \"평가용\"으로 따로 빼고, 이 100건은 예시로 쓰지 않습니다." / "자동 결과와 사람이 붙인 라벨을 비교해 서비스, 유형, 세부 유형별 일치율을 냅니다." / "차이가 숫자로 보이면 방향 결정이 쉬워집니다." 샘플과 비교 대상은 구체적이다. 가정을 기각할 관찰 결과(기준값)는 제시하지 않았다.
- 실패 후 행동: 1 — 근거: "틀린 패턴을 기준표와 예시에 반영하고 재채점 (정확도가 오를 때까지 반복)" / "원인이 기준표 모호함인지, 예시 부족인지, 모델 한계인지 분류합니다." 같은 평가 세트로 재채점하는 점은 있다. 바꿀 설계 요소는 "반영" 수준으로 포괄적이고, '모델 한계'로 판정했을 때의 조치는 없다.
- 사용자 개입 판단: 1 — 근거: "이때 API 키 발급, 개인정보 마스킹 여부, 회사의 외부 API 사용 정책도 같이 확인하세요." / "리뷰 데이터를 외부 AI API로 보내도 되는지 회사 정책을 확인해 주세요." 정책과 권한 확인은 요청했다. 응답자가 시도할 조치와 비용·권한·서비스 요구가 바뀌어 사용자 결정이 필요한 조건을 구별하지는 않았다.

두 응답의 구현 첫날 첫 행동은 실질적으로 같다. 둘 다 이미 손으로 라벨링한 최근 몇 개월분 리뷰 데이터를 모으는 일이며, R-7BFC가 200건 샘플링과 개인정보 확인을 덧붙인 정도의 차이다.
