### 응답 R-F900
- 구현 첫날 첫 행동(응답 문장 그대로 인용): "코드를 보낼 수 있는 모델 경로가 승인되었는지 확인합니다. 안 됐다면 오늘 할 일은 승인 요청과 공개 오픈소스 앱(예: 취약 앱 벤치마크)으로의 대체입니다."
- 채점한 최우선 제안(응답 문장 그대로 인용, 없으면 '없음'): "권고: 둘 다 1차 방식으로 쓰지 말고, "에이전트형 탐색 + 정적 분석 보조"로 시작하세요."
- 실제 문제와 일치: 2 — 근거: "취약점은 "의미가 비슷한 코드"가 아니라 **입력 → 검증 → 위험 함수로 이어지는 흐름**에 있습니다. 유사도 검색은 이 흐름의 중간 조각(권한 체크 누락, 헬퍼 함수 등)을 놓치기 쉽습니다." / 평가자용 기록 실패 1(벡터 검색이 코드 간 연관관계를 놓침)과 대응한다. 발생 조건(유사도로 조각을 골라 가져올 때)도 짚었다. 압축 방식에 대한 "들어가더라도 긴 컨텍스트에서 정확도가 떨어지며"는 실패 3(없는 취약점을 만들거나 흐름을 잘못 읽음)을 구체적으로 짚지 못했다. 실패 4(실행마다 결과가 달라짐)는 언급하지 않았다.
- 실험의 판별력: 1 — 근거: "중간 규모의 서비스 1~2개를 고르고, 이미 알려진 취약점 3~5개를 정답 목록으로 정리합니다(위치, 유형, 심각도)." / "정답이 있는 진입점과 없는 진입점을 섞어 돌립니다." 샘플은 구체적이다. 그러나 검토 중인 두 방식이나 다른 기준선과 비교하지 않는다. 가정을 기각할 관찰 결과나 기준도 제시하지 않았다.
- 실패 후 행동: 2 — 근거: "예를 들어 오탐이 많으면 검증 에이전트를, 놓침이 많으면 호출 그래프/정적 분석 도구 연동을 먼저 합니다." 바꿀 설계 요소가 관찰 유형별로 구체적이다. "정답 기반 평가 스크립트"로 같은 정답 세트에서 개선을 다시 확인할 수 있다.
- 사용자 개입 판단: 1 — 근거: "소스코드를 어떤 모델 엔드포인트로 보낼 수 있는지 보안/법무 승인을 받아야 합니다." 데이터 반출 권한 하나만 사용자 결정 조건으로 구별했다. 비용 상한, 범위 변경 등 다른 결정 조건과 직접 시도할 조치를 나눈 구분은 없다.

### 응답 R-F6C4
- 구현 첫날 첫 행동(응답 문장 그대로 인용): "**파일럿 대상 선정**: 언어와 프레임워크가 다른 서비스 2~3개를 고릅니다. 크기가 중간 정도이고 과거 취약점 이력이 있는 서비스가 좋습니다."
- 채점한 최우선 제안(응답 문장 그대로 인용, 없으면 '없음'): "제가 권하는 방향은 에이전트가 도구로 코드를 직접 탐색하게 하고, 임베딩은 보조 도구로만 두는 것입니다."
- 실제 문제와 일치: 2 — 근거: "의미가 비슷한 코드를 찾는 임베딩은 이 흐름을 따라가는 데 약합니다. 단독으로 쓰면 sink만 보이고 source나 sanitizer는 빠지기 쉽습니다." / 평가자용 기록 실패 1(벡터 검색이 코드 간 연관관계를 놓침)과 대응한다. 파일 간 source→sink 흐름이라는 발생 조건도 짚었다. 실패 3과 실패 4는 구체적으로 다루지 않았다.
- 실험의 판별력: 2 — 근거: "**입력**: 위 정답 세트(알려진 취약점 15~20개와 안전 코드 몇 개)입니다." / "A. 상한선 … B. 에이전트 탐색 … C. 임베딩 top-k … D. (선택) Semgrep/CodeQL 기본 규칙" / "B가 C보다 뚜렷하게 낫지 않으면(탐지 건수 차이가 1~2건 이내), 에이전트 방식의 추가 비용을 정당화하기 어렵습니다."
- 실패 후 행동: 2 — 근거: "도구 보강: 정의/참조 조회, 호출 그래프, CodeQL 결과를 에이전트에 제공합니다." / "실패 사례를 유형별로 분류해(컨텍스트 미수집, 판단 오류, 프레임워크 암묵 동작 등) 원인을 보고합니다." 같은 하네스와 정답 세트로 다시 비교할 수 있다.
- 사용자 개입 판단: 2 — 근거: "**제가 직접 시도할 수 있는 조치** (추가 승인 없이 파일럿 범위 안에서)" / "**사용자 결정이 필요한 조건**: 소스코드를 외부 LLM API로 보낼 수 있는지 … 비용이나 토큰 예산 상한을 올려야 할 때 … 실제 서비스에 동적 검증(재현 요청 실행)을 허용할지"

두 응답의 구현 첫날 첫 행동은 다르다. R-F900은 모델 반출 경로 승인 확인으로 시작해 당일 최소 에이전트를 돌리고, R-F6C4는 파일럿 서비스 선정으로 시작해 정답·증거 슬라이스와 하네스 구축에 첫날을 쓴다.
