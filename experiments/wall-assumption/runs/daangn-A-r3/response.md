# 앱 리뷰 자동 라벨링 도구: 초기 설계안과 첫날 계획

## 먼저 짚을 점: 키워드 매핑은 첫 도구로 부적합합니다

말씀하신 제약("문장이 정돈되어 있지 않고 맥락 판단이 필요하다")은 키워드 매핑이 가장 약한 지점입니다. 예를 들어 "결제 눌렀는데 안 넘어가서 그냥 택시 탔어요"는 '결제'라는 단어가 있어도 결제 오류 불만인지 이탈 사례인지 키워드로는 알 수 없습니다. 키워드 방식으로 먼저 만들면 오분류를 고치려고 규칙이 계속 늘어나고, 결국 손으로 라벨링하는 시간이 그대로 남을 가능성이 큽니다.

그래서 **LLM(생성형 AI)에게 라벨 기준표와 예시를 주고 분류시키는 방식**을 첫 도구로 제안합니다. 코딩 경험이 적어도 만들 수 있고, 맥락 판단이 필요한 문제에 더 맞습니다. 키워드 매핑은 "LLM이 얼마나 나은지" 비교하는 기준선으로만 쓰면 됩니다.

## 설계안

```
[리뷰 원본 CSV/엑셀]
        ↓
[1. 전처리] 중복·빈 리뷰 제거, 개인정보(전화번호·이메일 등) 마스킹
        ↓
[2. LLM 분류] 라벨 기준표 + 예시(few-shot) → JSON으로 출력
   {관련 서비스, 유형, 세부 유형, 확신도, 근거 한 줄}
        ↓
[3. 검수 분류] 확신도 낮음/복수 해석 가능 → "검토 필요" 표시
        ↓
[4. 사람 검수] 검토 필요 건만 확인·수정 (전체의 10~20%가 목표)
        ↓
[5. 출력] 라벨 붙은 CSV → 월간 리포트 시각화(피벗/차트)
        ↓
[6. 피드백] 수정된 건을 예시에 추가 → 다음 달 정확도 개선
```

**핵심 설계 결정**
- **라벨 기준표를 문서로 만든다.** 서비스, 유형, 세부 유형 각각의 정의, 경계 사례, 예시 2~3개를 적습니다. 도구의 품질은 사실상 이 문서가 결정합니다.
- **과거에 손으로 붙인 라벨이 곧 정답지다.** 이미 있는 라벨링 데이터를 평가용(정답 세트)과 예시용으로 나눠 씁니다.
- **완전 자동이 아니라 "사람은 애매한 것만 본다".** 6시간을 0으로 만들기보다 1시간 안팎으로 줄이는 것이 현실적인 목표입니다.
- **구조화된 출력.** 라벨 목록 외의 값이 나오지 않도록 허용 값을 프롬프트에 명시하고, 코드에서 한 번 더 검증합니다.
- **단순한 구성.** Python 스크립트 하나와 CSV 입출력으로 시작합니다. 웹앱이나 DB는 필요 없습니다.

## 구현 첫날 할 일

목표는 **"도구 완성"이 아니라 "이 방식이 되는지 숫자로 확인"**입니다.

1. **데이터 모으기 (30분)**: 최근 1~2개월간 손으로 라벨링한 리뷰 파일을 한 곳에 모읍니다. 컬럼은 리뷰 본문, 서비스, 유형, 세부 유형이면 충분합니다.
2. **라벨 기준표 초안 작성 (1시간)**: 현재 쓰는 라벨 목록을 표로 정리하고, 라벨마다 한 줄 정의와 실제 리뷰 예시 1~2개를 붙입니다. 헷갈렸던 경계 사례도 적어 둡니다. AI 코딩 도구에 기존 라벨 데이터를 주고 초안을 뽑게 한 뒤 직접 고치면 빠릅니다.
3. **데이터 분리 (15분)**: 라벨된 리뷰 중 약 100건을 "평가용"으로 따로 빼고, 이 100건은 예시로 쓰지 않습니다.
4. **최소 프로토타입 (2시간)**: AI 코딩 도구에 "CSV를 읽어 각 리뷰를 LLM API로 분류하고 결과를 CSV로 저장하는 Python 스크립트"를 요청합니다. 처음에는 평가용 100건만 돌립니다. 이때 API 키 발급, 개인정보 마스킹 여부, 회사의 외부 API 사용 정책도 같이 확인하세요.
5. **채점 (1시간)**: 자동 결과와 사람이 붙인 라벨을 비교해 서비스, 유형, 세부 유형별 일치율을 냅니다. 틀린 건을 직접 훑으면서 원인이 기준표 모호함인지, 예시 부족인지, 모델 한계인지 분류합니다.
6. **키워드 기준선 (선택, 30분)**: 원래 생각하신 키워드 매핑도 같은 100건에 돌려 비교합니다. 차이가 숫자로 보이면 방향 결정이 쉬워집니다.

**첫날 종료 시 얻을 것**: 라벨 기준표 v0.1, 100건 정답 세트, 라벨별 정확도 표, 틀리는 패턴 목록.

## 다음 단계 (2~5일차 개요)
- 틀린 패턴을 기준표와 예시에 반영하고 재채점 (정확도가 오를 때까지 반복)
- "확신도 낮음" 기준을 정해 검수 대상 비율 조정
- 월간 전체 데이터에 적용하고, 리포트용 피벗/차트 템플릿 연결
- 매일 쓸 수 있게 "파일 넣고 실행 → 결과 CSV" 한 줄 실행 방식으로 정리

## 확인이 필요한 질문
1. 라벨 종류는 서비스, 유형, 세부 유형 각각 몇 개인가요? (세부 유형이 수십 개 이상이면 계층적으로 나눠 분류하는 설계가 필요합니다.)
2. 하루 리뷰는 몇 건이고, 리뷰 데이터는 어디서 어떤 형식으로 받나요?
3. 과거에 라벨링한 데이터가 몇 건 정도 있나요? (수백 건 이상이면 충분합니다.)
4. 한 리뷰에 여러 서비스나 유형이 섞이는 경우가 있나요? (복수 라벨 허용 여부)
5. 리뷰 데이터를 외부 AI API로 보내도 되는지 회사 정책을 확인해 주세요.

이 답변을 알려주시면 라벨 기준표 양식과 첫 프로토타입용 프롬프트를 구체적으로 작성해 드리겠습니다.
