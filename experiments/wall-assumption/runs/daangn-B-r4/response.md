# 초기 설계안: 리뷰 자동 라벨링 도구

## 1. 핵심 판단
말씀하신 "키워드 → 서비스/유형 매핑"은 제약(문장이 정돈되지 않고 맥락 판단 필요)과 충돌합니다. 그래서 키워드 매핑을 **주 분류기가 아니라 비교 기준선(baseline)** 으로 두고, 주 설계는 **LLM 분류 + 사람 검수** 로 제안합니다.

## 2. 설계안

**흐름**
1. 리뷰 입력 (CSV/엑셀)
2. LLM이 리뷰별로 `관련 서비스 / 유형 / 세부 유형 / 확신도` 출력
3. 허용 라벨 목록(택소노미) 밖의 값은 거부 (고정 목록에서만 선택)
4. 확신도가 낮거나 라벨이 애매한 건만 사람 검수 목록으로 분리
5. 결과를 엑셀로 저장 → 월간 리포트 시각화에 사용

**구성 요소**
- 라벨 정의표: 서비스·유형·세부 유형 목록과 각 항목의 설명, 경계 사례 예시 (이미 손으로 붙인 라벨이 기반)
- 분류 프롬프트: 정의표 + 소수의 예시(few-shot)를 포함
- 검수 시트: 낮은 확신도 건만 모아 사람이 수정
- 정답 데이터(골든 셋): 기존 수작업 라벨 200~300건. 평가 전용이고 학습·예시와 분리

**도구 선택**: 코드를 거의 안 쓰는 길을 우선합니다. 파이썬 스크립트 하나(입력 파일 → 출력 파일)로 시작하고, 웹 화면·DB·자동 스케줄링은 만들지 않습니다.

## 3. 구현 첫날 할 일
코드보다 **데이터 준비**가 먼저입니다.
1. 지금까지 붙인 수작업 라벨이 있는 리뷰를 내보내 파일 하나로 모읍니다.
2. 라벨 값 목록을 뽑아 표기가 흔들리는 곳(띄어쓰기, 비슷한 이름)을 정리합니다. 이것이 택소노미 초안입니다.
3. 최근 리뷰 중 250건 정도를 무작위로 골라 골든 셋으로 따로 보관합니다.
4. 그 셋의 라벨 분포를 봅니다. 특정 라벨이 거의 없거나 "기타"가 많은지 확인합니다.
5. 시간이 남으면 키워드 기준선을 만들어 골든 셋 정확도를 측정합니다.

## 4. 틀리면 설계가 크게 바뀔 가정 하나
**"내 수작업 라벨이 일관적이어서, 라벨 정의표만으로 기준을 설명할 수 있다."**

라벨이 담당자 머릿속 판단이나 시기별 기준 변화에 의존한다면, 정의표와 예시로 LLM에 기준을 전달할 수 없습니다. 이 경우 설계는 "정의표 + 프롬프트"에서 "기준 재정립 먼저, 그다음 자동화"로 바뀝니다. 정답 자체가 흔들리기 때문에 어떤 방식도 정확도를 평가할 수 없습니다.

## 5. 가장 작은 실험

- **입력**: 골든 셋에서 무작위 100건. 같은 100건을 시간을 두고(예: 며칠 뒤) 라벨을 가리고 다시 직접 라벨링합니다.
- **비교 대상**: 과거 라벨 vs 이번 재라벨 (본인 vs 본인). 보조로 LLM 라벨 vs 과거 라벨도 같이 봅니다.
- **실패 판단**: 
  - 본인 일치율이 약 80% 미만이거나, 특정 유형·세부 유형에서 불일치가 몰리면 실패(기준이 일관적이지 않음). 
  - 80%는 임의의 시작 기준이므로 첫 결과를 보고 조정해도 됩니다.
  - LLM 일치율이 본인 재라벨 일치율보다 크게 낮은 것도 신호입니다. 이 경우 문제는 프롬프트나 정의표에 있습니다.
  - 불일치가 "어느 한쪽이 틀림"이 아니라 "둘 다 말이 되는" 형태라면, 택소노미 중복이 원인입니다.

## 6. 실패 시 조치

**직접 시도할 수 있는 조치 (사용자 결정 불필요)**
- 불일치 건을 모아 유형별로 분석하고, 정의표 문구와 경계 사례 예시를 보강
- 겹치는 세부 유형 후보를 정리안으로 작성해 제안
- 프롬프트의 예시를 불일치가 많은 라벨 중심으로 교체하고 골든 셋으로 재측정
- 확신도 기준을 낮춰 검수 대상 비율을 조정해 보기

**사용자 결정이 필요한 조건**
- 택소노미를 실제로 합치거나 삭제하거나 새로 만들어야 할 때 (리포트의 과거 데이터와 비교 가능성이 바뀜)
- 본인 일치율이 계속 낮아 "어느 기준이 맞는지" 정해야 할 때 (조직의 판단 기준)
- 자동화 비율과 오류 허용 수준: 예를 들어 검수 없이 자동 확정할 확신도 선, 월 리뷰 수 대비 검수 시간
- 리뷰 원문을 외부 LLM API로 보내도 되는지 (개인정보·사내 보안 정책 확인 필요)
- 비용이 월 예산을 넘을 때

## 7. 키워드 매핑 방식에 대해
완전히 버리지 않습니다. 기준선으로 먼저 정확도를 재면, LLM 방식이 실제로 얼마나 나은지 숫자로 확인되어 판단 근거가 됩니다. 단, 키워드 도구를 먼저 완성도 있게 만드는 데 시간을 쓰는 것은 권하지 않습니다.

원하시면 첫날 1~3단계를 위한 데이터 정리 스크립트부터 같이 만들어 드리겠습니다. 라벨 데이터가 어떤 형식(엑셀, 시트, 관리 툴)에 있는지 알려주세요.
