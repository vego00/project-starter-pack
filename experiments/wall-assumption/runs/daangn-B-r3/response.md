# 초기 설계안

## 핵심 판단
키워드 매핑만으로 시작하면 "문장이 정돈되지 않고 맥락 판단이 필요하다"는 제약과 충돌합니다. 그래서 **LLM 분류를 중심에 두고, 사람의 기존 라벨을 정답지로 삼아 검증하는 구조**를 제안합니다. 키워드 매핑은 버리지 않고 비교 기준선(baseline)으로 씁니다.

## 구조 (단순하게)
1. **입력**: 리뷰 CSV/엑셀 (리뷰 ID, 본문, 날짜, 별점)
2. **분류기**: LLM에 라벨 체계(관련 서비스 / 유형 / 세부 유형의 정의와 예시)를 프롬프트로 주고, 리뷰별로 JSON 라벨과 짧은 근거, 확신도를 받음
3. **검수 큐**: 확신도가 낮거나 "기타/모호"인 리뷰만 사람이 확인
4. **출력**: 라벨이 붙은 CSV → 기존 시각화/리포트에 그대로 사용
5. **평가 스크립트**: 사람이 붙인 라벨과 비교해 일치율과 혼동 항목을 표로 출력

개발 경험이 적으므로 처음엔 스크립트 1개 + 설정 파일(라벨 정의) 1개로 시작하고, 웹 화면이나 DB는 만들지 않습니다.

## 구현 첫날 할 일
1. **데이터 준비(코딩 전)**: 이미 손으로 라벨링한 과거 리뷰 중 최근 2~3개월분에서 200건 정도를 뽑습니다. 개인정보(이름, 연락처 등)가 있는지 확인합니다.
2. **라벨 체계 문서화**: 서비스·유형·세부 유형 목록과 각 정의, 헷갈리는 경계 사례를 한 장으로 적습니다. 이 문서가 곧 프롬프트가 됩니다.
3. **데이터 분할**: 50건은 프롬프트 조정용, 150건은 평가용으로 분리해 건드리지 않습니다.
4. **키워드 baseline**: 현재 구상한 매핑을 가장 단순하게 만들어 평가용 150건에 돌립니다(1~2시간).
5. **LLM 분류 시험**: 같은 150건을 LLM으로 돌려 비교합니다.

## 뒤집힐 수 있는 핵심 가정
**"기존 수작업 라벨이 일관된 정답지다"**

이 가정이 틀리면 설계가 크게 바뀝니다. 라벨 기준이 사람·시기마다 흔들리거나 세부 유형이 모호하면, 어떤 자동화 방식이든 일치율이 낮게 나옵니다. 이 경우 문제는 모델이 아니라 라벨 체계이므로, 도구보다 분류 체계 재정의(세부 유형 통합 등)가 먼저입니다.

(키워드가 부족하다는 가정은 이미 제약에 명시되어 있어 검증 우선순위가 낮습니다. 다만 baseline 비교로 수치로 확인합니다.)

## 가장 작은 실험
- **입력**: 과거 리뷰 중 무작위 50건. 이를 **같은 사람이 시간을 두고(며칠 뒤) 다시 라벨링**한 결과를 만들고, 원래 라벨과 비교합니다. 가능하면 동료 1명이 독립적으로 붙인 라벨도 추가합니다.
- **비교 대상**: 원래 라벨 vs 재라벨(및 동료 라벨). 서비스 / 유형 / 세부 유형 각각의 일치율을 따로 봅니다.
- **실패 판단**: 사람끼리(또는 본인끼리)의 일치율이 낮은 경우. 구체적으로 서비스 라벨 90% 미만, 유형 80% 미만, 세부 유형 70% 미만이면 정답지로 쓰기 어렵다고 봅니다. (기준값은 임시이며, 리포트에 필요한 정확도에 맞춰 조정하세요.)

## 실패 시 조치

**제가 직접 시도할 수 있는 것**
- 불일치 건을 표로 모아 어떤 라벨 쌍에서 혼동이 나는지 분석
- 혼동이 큰 세부 유형의 정의 문장과 경계 예시를 다시 쓰는 초안 작성
- 비슷한 세부 유형을 합치거나 "기타"를 추가하는 안 2~3개 제시
- 수정한 정의로 같은 50건을 다시 실험해 일치율 변화 측정

**사용자 결정이 필요한 것**
- 라벨 체계 자체를 바꿀지 (세부 유형 통합/삭제는 기존 월간 리포트와의 연속성에 영향)
- 리포트에 필요한 정확도 수준이 어디까지인지 (세부 유형을 포기하고 서비스·유형만 자동화할지 포함)
- 리뷰 데이터를 외부 LLM 서비스에 보내도 되는지 (사내 정책, 개인정보)
- 동료에게 라벨링을 요청하는 시간과 비용
- 자동 라벨 후 검수를 어느 범위까지 사람이 할지 (예: 확신도 낮은 20%만)

## 기대 효과
정답지가 믿을 만하다면, 대다수를 자동 처리하고 낮은 확신도 건만 검수하는 방식으로 월 6시간 중 상당 부분을 줄일 수 있습니다. 실제 절감 폭은 baseline 대비 LLM의 일치율을 측정한 뒤에 말할 수 있습니다.
